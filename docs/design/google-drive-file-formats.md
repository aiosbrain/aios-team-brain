## Problem, decision and falsification

The inspected AIO-1167 dependency snapshot enumerates only Google Docs in selected folders. Inspected staging still has the legacy LlamaHub wrapper (`ingestion/aios_ingest/sources/gdrive.py`); the Docs-only statement describes the dependency being extended, not shipped staging. Sheets, Slides and uploaded files disappear from the importer's view, so administrators cannot distinguish unsupported content from an empty folder. Extend source `gdrive` with MIME-based extraction and explicit metadata-only outcomes, retaining AIO-1167's file identity, traversal, credential broker, durable change feed, authority, audience claims, contribution evidence and run reporting. Every selected non-folder file receives a reported outcome; none is silently dropped because of its format.

The deliverable in this PR is this specification. The read-only AIO-1167 worktree is at `4fbbafa32f3d2c8fd91b3d7591851f3ad468cfbc`, based on `5b9400e7`; the local `origin/staging` snapshot inspected here is `c5e832c2ff179ee5c99f95966fba1ed9ce77ae3e`. AIO-1167 is not a stackable current-staging base. Its owner must rebase it onto current staging, reconcile the PR 714 behavior and shipped migrations, set the correct remote upstream and push before format implementation starts. Refresh these identities at that handoff. A backup push is recovery evidence, not readiness to stack.

Alternatives rejected: CSV export for Sheets loses all but the first tab; Office conversion introduces provider writes and a new resource/identity; a separate connector or per-format sink duplicates authority; OCR introduces a new quality/cost pipeline; character-only caps do not bound JSON transport; dropping unsupported files hides coverage. The chosen Office path is bounded local OOXML parsing, not conversion. A complete extraction means all supported readable content in the declared format profile was examined without a cap, missing segment or parsing failure. It does not promise visual fidelity. Completeness is relative to the versioned `readable_text_v1` profile below. Non-text visuals outside that profile are disclosed without blocking complete text; omitted supported text or an unclassifiable text-bearing object is blocking. A scan/outlined-text PDF cannot be treated as an empty complete document.

This decision is falsified by any AC failure below, especially a lost second sheet, omitted notes reported complete, an unauthorized non-Doc read, a format-dependent identity change, an unchanged sync adding activity, or a request exceeding the actual byte gate. Missing authenticated live evidence blocks certification even if all fixtures pass.

## One extraction contract and persistence policy

Keep the AIO-1167 dependency snapshot’s public `DocsExtraction(text: str, complete: bool, tabs: list[dict], issues: list[ExtractionIssue])` and `ExtractionIssue(code, location, detail, blocking=False)` shape from planned dependency file, not present on inspected staging: `ingestion/aios_ingest/sources/gdrive_docs.py` (not present on inspected current staging). Share those types with new extractor modules; do not invent a parallel result type. Preserve the existing import path if declarations move. `extract_google_doc` and its output text, ordering, tabs, issues and completeness stay byte-identical for identical inputs/configuration. Its current character guard is retained; the common outbound transport guard is additional. Existing Docs incomplete-body rejection remains unchanged.

For new formats, `tabs` is an ordered segment manifest using `id`, `title`, zero-based `order`, `parent_id: null`, `nesting_level: 0`. Sheets use provider sheet IDs; Slides use slide object IDs; PDF uses `page:1`, etc.; DOCX uses `document`; XLSX uses stable workbook sheet names; PPTX uses slide IDs where available (otherwise index with an explicit diagnostic); text uses `file`. Metadata-only has `tabs=[]`. Every attempted segment is represented, including empty ones. A missing segment is not an empty segment. Segment-level issue locations use these IDs plus row/cell/element paths. New issues use bounded, sanitized details; no credentials, source excerpts or raw parser stack traces enter run errors.

Every new extractor returns the shared contract. Complete supported text has `complete=true`; unsupported, parse-rejected or omitted supported text has `complete=false`. The following code policy is exhaustive for new formats; issue severity is fixed by code, never guessed from detail text. Preserve Docs' existing issue names/semantics.

| Issue codes | Blocking / meaning |
|---|---|
| `non_text_omitted`, `profile_exclusion`, `display_limitation`, `encoding_fallback` | false: respectively visual/media omission, a declared profile exclusion, raw numeric/date display, or lossless fallback. They permit complete text and remain visible in Admin |
| `unsupported_mime`, `unsupported_profile`, `no_text_layer`, `encrypted_pdf`, `parse_error`, `unsupported_element`, `missing_segment`, `encoding_error`, `invalid_json`, `missing_formula_cache`, `unsafe_xml` | true: unsupported input or omitted/unreadable supported text |
| `row_limit`, `column_limit`, `cell_limit`, `cell_byte_limit`, `text_length_limit`, `text_byte_limit`, `download_byte_limit`, `api_response_limit`, `segment_limit`, `parser_resource_limit`, `archive_limit`, `envelope_limit` | true: specified resource bound prevents a complete result |
| `capability_scope_missing`, `capability_api_disabled`, `download_restricted`, `sink_rejected`, `parser_sandbox_unavailable` | true: terminal attempt/action required, using the capability settlement protocol below |
| `provider_revision_changed` | true for the discarded attempt; coordinator retries without publishing it as a settled incomplete file |

Transient failures are coordinator failures, not fabricated successful extraction. Unknown new issue codes fail validation until added to this registry. `text_length_limit` measures UTF-16 code units; `text_byte_limit` means body-containing wire overflow; `envelope_limit` means even a safe metadata operation cannot fit.

New-format item frontmatter retains `source: gdrive`, `source_id`, the canonical path and all current authority/contribution fields; add `gdrive_mime_type` (normalized token), `gdrive_format`, `gdrive_format_profile: readable_text_v1`, `extraction_mode` (`text` or `metadata_only`), `extraction_complete`, `extraction_issues`, `gdrive_tabs`, and `extracted_modified_time`. These fields describe the stored body, not the latest attempt. A separate bounded `gdrive_latest_attempt` object records `{provider_version, modified_time, mime_type, status, issues}` when a new-format attempt cannot replace a complete body. Do not mutate source work time to the attempt/run clock.

| Outcome | First authorized import | Existing item | Run classification |
|---|---|---|---|
| Supported, complete | Store extracted text and `extraction_complete=true` | Replace through ingest owner, preserving versions | `ingested` |
| Supported, deterministic incomplete (cap, scanned/encrypted/malformed content, missing segment) | Store only the safe metadata body, `extraction_mode=metadata_only`, `extraction_complete=false`, blocking issue; do not publish a partial excerpt as complete text | Retain last complete body for the same MIME, its extraction fields and source timestamp; update latest-attempt diagnostics and current audience. If no complete body exists, update metadata placeholder | `incomplete` |
| Unsupported MIME | Store safe metadata body, `extraction_mode=metadata_only`, `extraction_complete=false`, `unsupported_mime` | Replace obsolete extracted body with current metadata when MIME changed; preserve old versions behind current access | `metadata_only` |
| Terminal capability/envelope/sink validation failure | No new item; authorized status record required | No replacement; apply current authority and record standing failure | `failed`, nonretryable until remedy |
| Transient network/auth/provider error or retryable sink refusal | No new item | No content replacement; follow dependency's authority/revocation behavior | `failed`, retryable/pause as below |

The metadata body contains escaped title, safe Drive link, owner provenance (or “unresolved/not supplied”), MIME and provider modified time, plus the extraction status. It contains no binary payload or text guessed from a name. Store only metadata the provider actually supplied. Metadata-only does not mean public: its title and owner follow the same audience as full text. Never synthesize an owner on Shared Drives.

For a same-ID MIME change, dispatch again and keep the same canonical item. If the new format is incomplete, replace old-format content with an incomplete metadata placeholder; retaining a complete body is allowed only for the same MIME. If conversion creates a new Drive ID, it is a new item; do not merge by name, extension or content hash. The original remains until authoritative removal/membership rules remove it. The new representation and all retained versions obey current audience. A transient extraction error cannot be used to widen access or postpone a confirmed revocation.

Deterministic incomplete/unsupported outcomes settle a durable file obligation only after its item/status commit. Terminal action-required failures settle after an authorized durable status commit even when no item can be written; their extraction coverage is `partial`. Retry deterministic extraction outcomes on a later provider version or explicit retry, and capability failures on an explicit retry or recorded capability/configuration change. Transient failures retain the existing durable retry path. A complete selection snapshot means enumeration is authoritative, not that every file's extraction is complete.

### Owned retention operation

GDRIVEFMT-1 owns the additive wire/schema/client and server merge changes after AIO-1167's authority seam is accepted. Update the pinned API contract first. Add optional top-level `gdriveExtraction` to the item payload, with `{operation: "replace" | "retain_complete", attempt: {providerVersion, modifiedTime, mimeType, status, issues}, fallbackBody}`; `fallbackBody` is required only for `retain_complete` and is the safe metadata representation. The ordinary body for that operation is empty, never a downloaded prior body. The sidecar sends current authority/evidence through the dependency envelope and never reads/replays old content. For item operations, `attempt.status` is `ingested|incomplete|metadata_only`; `replace` permits complete text or unsupported-MIME metadata, and `retain_complete` requires an incomplete supported-format attempt. Terminal/retryable `failed` statuses use the run-report protocol, never a fabricated item operation. Wire camelCase maps explicitly to the documented snake_case frontmatter fields; `providerVersion` is stored in latest-attempt diagnostics as `provider_version`. Server responses add `gdriveDisposition: "replaced" | "retained_complete" | "metadata_fallback"`, used for verified run reporting. Unsupported clients/servers must reject this extension explicitly; no silent downgrade to an ordinary empty-body write.

In `app/api/v1/items/route.ts`, `lib/api/item-payload-schema.ts`, the sidecar payload model/`brain_client.py`, and `lib/ingest/index.ts`, the assigned GDRIVEFMT implementation writer adds this protocol. Inside the dependency's authorized execution transaction, lock/re-read the canonical item, validate the current obligation/provider version against the accepted dependency freshness fence, then choose retention only if the stored body is complete text of the same normalized MIME. Preserve body/hash, stored extraction metadata/manifest, source-time keys, `work_at`, contribution and version records byte-for-byte; merge only bounded `gdrive_latest_attempt`, synchronization freshness and currently authorized audience/claims. Do not run the ordinary wholesale-frontmatter/unchanged-work-time merge on this branch. If there is no eligible body (including MIME change), write the validated `fallbackBody` with incomplete metadata fields through the same owner. Revocation is applied even if there is no replacement body. No other source or untrusted principal may invoke this operation.

A retained incomplete attempt produces **no contribution or timeline event**, even if the provider edit has valid human evidence. That evidence remains attached to the durable attempt; a later complete accepted extraction can consume it once through the dependency's deduplication path. Successful complete and metadata-placeholder writes retain ordinary gdrive source policy, including a proven metadata-only human edit; run/parser/access-only changes never count as work. Concurrent older attempts cannot replace newer complete content or newer diagnostics. AC-10 and AC-14 require these branches explicitly; the shared source-wide rule itself is unchanged.

A malformed token is `other`; absent MIME first requires metadata refresh. Preserve the raw value only as bounded diagnostic metadata. Filenames/extensions never select a parser. Aliases in the matrix are exhaustive, never content sniffing into another parser. Folders are traversal nodes, not file items. The format rows map respectively to `docs`, `sheets`, `slides`, `pdf`, `docx`, `xlsx`, `pptx`, `text`/`markdown` (split by MIME), `csv`, `html`, `json`, `other`; that exact key is both `gdrive_format` and the `formatCounts` key.

### Declared `readable_text_v1` profile

| Content | Supported or explicitly excluded |
|---|---|
| Native Docs | Existing accepted dependency profile unchanged; no retrospective new-format issue policy |
| Sheets | All GRID formatted cell values, including hidden tabs; cell notes/comments are excluded with informational `profile_exclusion` (declare the exclusion even when their presence is not fetched). Embedded GRID charts and OBJECT/chart-only tabs are non-text omissions, retain a segment/heading and `non_text_omitted`. DATA_SOURCE/unknown tab types are blocking `unsupported_element` |
| Slides/PPTX | Text shapes, text boxes, groups, tables, notes BODY, hidden/skipped slides and supplied alt text are supported. Images/charts/video/animation/layout are non-text omissions. SmartArt/diagram text or unknown objects capable of carrying text are blocking `unsupported_element` unless fully rendered by the supported text walker. Comments are excluded with `profile_exclusion` |
| DOCX | Transitional OOXML body, tables, text boxes and named auxiliary sections are supported. Tracked insertions are included and deletions excluded (final document view), with `profile_exclusion` disclosing excluded revision history/comments. Images are non-text omissions; embedded documents, SmartArt and unreadable text containers block |
| XLSX | Transitional OOXML worksheet cells and cached formulas, including hidden sheets, are supported. Cell comments/notes are declared profile exclusions; charts/drawings are non-text omissions; unknown/non-worksheet parts that may carry supported cells block |
| All OOXML | Strict namespaces are detected and rejected with blocking `unsupported_profile`; never interpret an unrecognized namespace as empty text. Legacy/macro MIME remains unsupported. Unknown required parts, relationships or text containers fail closed |
| PDF | Extractable text layer is supported. With text present, visual images/vectors are disclosed as `non_text_omitted`. A page with zero extractable text and any painting operator/image/vector/Form content gets blocking `no_text_layer` (includes outlined text). A page is blank only after a bounded recursive inspection proves no painting content; inability to inspect is blocking. This does not promise OCR for lettering embedded in pictures on otherwise textual pages |

Informational omissions leave `extraction_complete=true`, `extraction_mode=text`, run bucket `ingested`; Admin labels this “Complete text; non-text/profile omissions” when applicable. Blocking omissions follow metadata/retention policy. Do not claim full visual or all-content completeness. The profile/exclusion disclosure is stored with the body, so repeat imports do not invent new activity.

Sheets ranges are quoted/escaped from provider names. For each GRID tab request the full allocated grid (metadata rowCount × columnCount) in non-overlapping rectangles of at most 2,000 rows × 100 columns, at most 20 ranges per call; each response is streamed under API byte bounds. A missing requested response is `missing_segment`; an explicitly returned empty value range is valid. Traverse rectangles and their values in deterministic tab/row/column order. Grid allocation and empty trailing cells do **not** consume the data-cell cap. Count every returned array cell position, including explicit empty values/interior gaps, but not omitted trailing cells/rows; rows/columns are absolute coordinates of nonempty returned values. Full-grid scanning under the byte/time/call bounds proves trailing emptiness; an unvisited tail can never be asserted empty. Cap scanning at 200 ranges per file; needing more is `api_response_limit` with reason `range_scan_limit` even if the file might be empty. Defaults of two 1,000 × 26 tabs therefore do not exceed 50,000 cells merely through allocation. The provider omits empty trailing cells from values responses ([ValueRange contract](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values)).

Report all already-observed limit codes, sorted by segment/coordinate then the fixed precedence `row_limit`, `column_limit`, `cell_limit`, `cell_byte_limit`; the first is the primary issue. Row >2,000 with a nonempty value gives `row_limit`, column >100 gives `column_limit`, the 50,001st returned cell position gives `cell_limit`, and an individual decoded cell >16,384 UTF-8 bytes gives `cell_byte_limit`. A single offending cell can yield multiple codes; resource termination does not invent findings in unvisited data. XLSX/CSV apply the same data limits to parsed values/positions (empty trailing records are ignored; interior positions count). Read provider metadata/version before and after multi-call extraction; a changed version discards the result and remains retryable. Unsupported visuals are disclosed, never captioned.

Google documents CSV/TSV export as first-sheet-only, and `files.export` limits exported content to 10 MB. This design uses native Sheets/Slides APIs rather than export, and local parsing rather than Office conversion. Any future export fallback must use a 10,000,000-byte ceiling and mark provider export refusal incomplete; it must not substitute a smaller export silently. [Drive export formats](https://developers.google.com/workspace/drive/api/guides/ref-export-formats), [Drive downloads](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

The Sheets API exposes metadata separately from values; notes have an explicit Slides BODY-shape identity. These are the API seams to test. [Sheets get](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get), [Sheets values](https://developers.google.com/workspace/sheets/api/guides/values), [Slides notes](https://developers.google.com/workspace/slides/api/guides/notes).

## Bounded resources and encoded-byte contract

At inspected staging `c5e832c2`, `app/api/v1/items/route.ts:24` defines `MAX_PAYLOAD=1_000_000`; line 49 defines `MAX_REQUEST_BYTES = ceil((MAX_PAYLOAD + MAX_PAYLOAD_ROWS * 700) * 1.2)`, currently **5,400,000 bytes**. Lines 61–65 compare Content-Length to that transport cap; the payload schema separately caps body string length at 1,000,000. The brief's implication that the request gate is 1 MB is stale: the error message's “body max 1 MB” names a different bound. Neither a Python character count nor JSONB's textual representation measures the actual request.

Derive the sidecar transport constant from the canonical server/API contract, with a cross-language drift test against the server expression/row constant; no unreviewed numeric copy. Before implementation changes the wire fields, update the pinned sibling-workspace contract `../aios-workspace/docs/brain-api.md` and its version as `RESOLVER.md` requires; this is an external workspace contract, not an existing file in this repository. No API change is made by this docs-only PR.

Use two independent units: `U=MAX_PAYLOAD=1,000,000` **UTF-16 code units** for the body string, and `R=MAX_REQUEST_BYTES=5,400,000` **UTF-8 encoded bytes** for the entire request. There is no 1,000,000-byte text cap. For example, 400,000 CJK characters (1,200,000 UTF-8 bytes / 400,000 UTF-16 units) pass if their full request fits `R`; 600,000 supplementary-plane characters fail `U` even when their bytes fit `R`. Reject unpaired surrogates as invalid encoding. Measure fallback metadata bodies against `U` as well as normal bodies; all operation fields count against `R`.

GDRIVEFMT owns the shared `BrainClient.push` serialization change and compatibility tests for its other callers. Add one serialization helper using JSON `ensure_ascii=False`, compact separators, `allow_nan=False`, strict UTF-8 encoding; measure those finalized bytes and send exactly that buffer through httpx `content=`, `Content-Type: application/json`, and exact Content-Length. Never measure one serialization and let `json=` produce another. Retry sends reuse identical bytes. Server stream enforcement/Content-Length checks and the body schema stay authoritative; cross-language fixtures prove Python's code-unit measure equals JS string length.

Fully render/measure the bounded candidate, including final authority, frontmatter and issues. Body >`U` is `text_length_limit`; a body-bearing request >`R` is `text_byte_limit`. Discard the complete candidate, produce the metadata/retention operation with the blocking issue, and reserialize that operation. There is **no shrinking/truncation loop** and no partial-text publication. If the bounded safe fallback operation still exceeds either applicable limit, emit terminal `envelope_limit` via the separate bounded run-status protocol and make no item write. The common exact-wire guard also applies to Docs without modifying renderer output: overflow refuses that item and reports terminal `envelope_limit`, preserving existing Docs incomplete rejection. Never cut identity/authority or silently drop manifest entries/issues to fit. Aggregate repeated diagnostics within the documented issue limit, with count and omitted-detail count; aggregation does not hide incompleteness.
Byte sizes below are exact; MiB means 1,048,576 bytes. Counts (rows, columns, cells, segments, entries) and seconds are separately labeled. Limits are checked on declared size when present AND actual streamed bytes (including decoded HTTP response bytes). Unknown/misleading Content-Length does not bypass a bound. Abort at cap+1; do not buffer first and check later.

| Resource | Default hard limit and response |
|---|---|
| Plain/Markdown/CSV/HTML/JSON download | 5 MiB per file, `download_byte_limit` |
| PDF or any supported OOXML download | 20 MiB compressed/input bytes per file, `download_byte_limit` |
| Native API response | 10 MiB decoded response per call, 40 MiB aggregate per file; `api_response_limit`; bounded batches of at most 20 Sheets ranges, at most 200 ranges per file |
| Segments | 200 tabs/slides/pages per file, `segment_limit`; manifest explicitly identifies unprocessed count when available |
| Sheets/XLSX/CSV data | Nonempty values within row 2,000 and column 100 per tab/table; 50,000 returned/parsed cell positions per file (not grid allocation); 16,384 UTF-8 bytes per cell. Codes/precedence are defined above; do not omit later tabs silently |
| OOXML archive | 2,000 entries, 100 MiB total actual inflated bytes, 10 MiB each entry, max compression ratio 100:1; `archive_limit` |
| Parser worker | One file per isolated subprocess, no network/credentials, 256 MiB memory ceiling, 30 seconds wall time; terminate and reap on resource limit; `parser_resource_limit` |
| Diagnostic envelope | At most 100 issue entries, 256 UTF-8 bytes per detail; aggregate count and omitted-detail count preserve the fact of incompleteness |

Choose `pypdf` for pure-Python packaging and text-layer extraction with no external OCR/runtime. Its content streams can inflate beyond input size, so download caps alone are insufficient; enforce worker memory/time limits before parsing. [pypdf text extraction](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md).

Choose a small read-only OOXML reader using Python `zipfile` plus `defusedxml.ElementTree` rather than library defaults whose XML paths need individual hardening. It is an equivalent local parser for this explicitly limited readable-text profile, not an Office renderer. Never extract archive paths onto the filesystem. Reject absolute/parent paths, duplicate ZIP names, symlinks, encrypted entries, inconsistent size/CRC, nested archives and unsupported compression. Count actual decompression bytes before XML parsing; validate central-directory bounds as an early check, not sole protection. Parse ALL consumed XML through defusedxml with DTD/entities/external references forbidden. Resolve only normalized in-package relationships; external relationships may be displayed as inert links but never fetched. No macros, formula evaluation or embedded code. Add `pypdf` to `ingestion/pyproject.toml`'s `gdrive` optional extra with a reproducible supported version chosen at implementation; `defusedxml` is already a core dependency and is reused. Verify production worker ceilings on supported deployment platforms; inability to enforce them fails closed for binary parsing, never silently runs an unbounded parser.

The binary parser production target is Linux: launch the parser with a verified bubblewrap sandbox using fresh user/network/PID/mount namespaces, no network interfaces/routes to the host, read-only minimal runtime, no inherited sockets or credentials, and only the bounded input plus a private disposable directory. Set `RLIMIT_AS=268435456` before loading input; the parent enforces 30 seconds with process-group termination and reaping. Tests intentionally attempt external/loopback sockets, large allocation and a hung child, and verify denial/termination with no surviving child. Python monkeypatching is not the isolation boundary. Deploy-time preflight must verify the actual namespace/kernel permissions and limit enforcement; absent bubblewrap, disabled namespaces or an unsupported platform returns terminal `parser_sandbox_unavailable` for PDF/OOXML. No unbounded fallback. Local non-Linux tests may use the verified Linux container target; certification must exercise the deployed runtime. Native API clients run in the credential broker process, not the no-credential parser sandbox.

Encoding order: BOM-declared UTF-8/UTF-16 first, strict UTF-8 otherwise, then strict Windows-1252 as the documented fallback. Record the selected encoding and `encoding_fallback`. Never use `errors=ignore` or replacement characters. Undefined Windows-1252 bytes or binary NULs outside valid BOM-decoded UTF-16 produce `encoding_error`; no complete text. The fallback is an explicit limited policy, not reliable detection of every world encoding.

## Identity, changes, people and access
