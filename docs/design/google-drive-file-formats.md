# GDRIVEFMT-1 — Google Drive file formats

Status: proposed specification; docs-only checkpoint. No format implementation or live certification is claimed.
Task: [AIO-1229](https://linear.app/je4light/issue/AIO-1229/ingest-drive-sheets-slides-pdf-office-and-text-files); brain row key `GDRIVEFMT-1`.
Dependencies: AIO-1167 (Drive connector) and the shared identity work in AIO-1170 / [PR 714](https://github.com/aiosbrain/aios-team-brain/pull/714).

## Problem, decision and falsification

Selected Drive folders currently enumerate only Google Docs. Sheets, Slides and uploaded files disappear from the importer's view, so administrators cannot distinguish unsupported content from an empty folder. Extend source `gdrive` with MIME-based extraction and explicit metadata-only outcomes, retaining AIO-1167's file identity, traversal, credential broker, durable change feed, authority, audience claims, contribution evidence and run reporting. Every selected non-folder file receives a reported outcome; none is silently dropped because of its format.

The deliverable in this PR is this specification. The read-only AIO-1167 worktree is at `4fbbafa32f3d2c8fd91b3d7591851f3ad468cfbc`, based on `5b9400e7`; the local `origin/staging` snapshot inspected here is `c5e832c2ff179ee5c99f95966fba1ed9ce77ae3e`. AIO-1167 is not a stackable current-staging base. Its owner must rebase it onto current staging, reconcile the PR 714 behavior and shipped migrations, set the correct remote upstream and push before format implementation starts. Refresh these identities at that handoff. A backup push is recovery evidence, not readiness to stack.

Alternatives rejected: CSV export for Sheets loses all but the first tab; Office conversion introduces provider writes and a new resource/identity; a separate connector or per-format sink duplicates authority; OCR introduces a new quality/cost pipeline; character-only caps do not bound JSON transport; dropping unsupported files hides coverage. The chosen Office path is bounded local OOXML parsing, not conversion. A complete extraction means all supported readable content in the declared format profile was examined without a cap, missing segment or parsing failure. It does not promise visual fidelity. Unsupported embedded content is disclosed and makes new-format extraction incomplete if it can contain omitted readable content.

This decision is falsified by any AC failure below, especially a lost second sheet, omitted notes reported complete, an unauthorized non-Doc read, a format-dependent identity change, an unchanged sync adding activity, or a request exceeding the actual byte gate. Missing authenticated live evidence blocks certification even if all fixtures pass.

## One extraction contract and persistence policy

Keep the existing public `DocsExtraction(text: str, complete: bool, tabs: list[dict], issues: list[ExtractionIssue])` and `ExtractionIssue(code, location, detail, blocking=False)` shape from `ingestion/aios_ingest/sources/gdrive_docs.py`. Share those types with new extractor modules; do not invent a parallel result type. Preserve the existing import path if declarations move. `extract_google_doc` and its output text, ordering, tabs, issues and completeness stay byte-identical for identical inputs/configuration. Its current character guard is retained; the common outbound transport guard is additional. Existing Docs incomplete-body rejection remains unchanged.

For new formats, `tabs` is an ordered segment manifest using `id`, `title`, zero-based `order`, `parent_id: null`, `nesting_level: 0`. Sheets use provider sheet IDs; Slides use slide object IDs; PDF uses `page:1`, etc.; DOCX uses `document`; XLSX uses stable workbook sheet names; PPTX uses slide IDs where available (otherwise index with an explicit diagnostic); text uses `file`. Metadata-only has `tabs=[]`. Every attempted segment is represented, including empty ones. A missing segment is not an empty segment. Segment-level issue locations use these IDs plus row/cell/element paths. New issues use bounded, sanitized details; no credentials, source excerpts or raw parser stack traces enter run errors.

All new extractors, including unsupported and parse-rejected files, return this contract with `complete=false` and blocking issues on omitted content. Transient provider/authority errors remain retryable coordinator failures rather than fabricated extraction success. Use stable issue codes: `unsupported_mime`, `no_text_layer`, `encrypted_pdf`, `parse_error`, `unsupported_element`, `missing_segment`, `row_limit`, `cell_limit`, `text_byte_limit`, `download_byte_limit`, `api_response_limit`, `segment_limit`, `parser_resource_limit`, `archive_limit`, `unsafe_xml`, `encoding_fallback`, `encoding_error`, `invalid_json`, `missing_formula_cache`, `provider_revision_changed`, `envelope_limit`. Only `encoding_fallback` is informational when decoding is lossless; malformed/omitted content issues are blocking. Preserve Docs' existing issue names and semantics.

New-format item frontmatter retains `source: gdrive`, `source_id`, the canonical path and all current authority/contribution fields; add `gdrive_mime_type`, `gdrive_format`, `extraction_mode` (`text` or `metadata_only`), `extraction_complete`, `extraction_issues`, `gdrive_tabs`, and `extracted_modified_time`. These fields describe the stored body, not the latest attempt. A separate bounded `gdrive_latest_attempt` object records `{modified_time, mime_type, status, issues}` when a new-format attempt cannot replace a complete body. Do not mutate source work time to the attempt/run clock.

| Outcome | First authorized import | Existing item | Run classification |
|---|---|---|---|
| Supported, complete | Store extracted text and `extraction_complete=true` | Replace through ingest owner, preserving versions | `ingested` |
| Supported, deterministic incomplete (cap, scanned/encrypted/malformed content, missing segment) | Store only the safe metadata body, `extraction_mode=metadata_only`, `extraction_complete=false`, blocking issue; do not publish a partial excerpt as complete text | Retain last complete body for the same MIME, its extraction fields and source timestamp; update latest-attempt diagnostics and current audience. If no complete body exists, update metadata placeholder | `incomplete` |
| Unsupported MIME | Store safe metadata body, `extraction_mode=metadata_only`, `extraction_complete=false`, `unsupported_mime` | Replace obsolete extracted body with current metadata when MIME changed; preserve old versions behind current access | `metadata_only` |
| Transient network/auth/provider error or sink refusal | No new item | No content replacement; follow dependency's authority/revocation behavior | `failed` |

The metadata body contains escaped title, safe Drive link, owner provenance (or “unresolved/not supplied”), MIME and provider modified time, plus the extraction status. It contains no binary payload or text guessed from a name. Store only metadata the provider actually supplied. Metadata-only does not mean public: its title and owner follow the same audience as full text. Never synthesize an owner on Shared Drives.

For a same-ID MIME change, dispatch again and keep the same canonical item. If the new format is incomplete, replace old-format content with an incomplete metadata placeholder; retaining a complete body is allowed only for the same MIME. If conversion creates a new Drive ID, it is a new item; do not merge by name, extension or content hash. The original remains until authoritative removal/membership rules remove it. The new representation and all retained versions obey current audience. A transient extraction error cannot be used to widen access or postpone a confirmed revocation.

Deterministic incomplete/unsupported outcomes can settle a durable file obligation after its item/status commit so one unreadable file cannot block cursor progress forever; their run status remains `partial`. Retry them on a later provider version or explicit retry. A transient failed obligation stays in the existing durable retry path. A complete selection snapshot means enumeration is authoritative, not that every file's extraction is complete.

## Format matrix

Dispatch solely on provider `mimeType` (normalized MIME token); filenames and extensions are display metadata. A mismatched extension must not select another parser. MIME aliases are an explicit tested allowlist, never content sniffing into an executable parser. Folders are traversal nodes, not file items.

| Format / MIME | Extraction and output | Manifest and incomplete conditions |
|---|---|---|
| Google Docs — `application/vnd.google-apps.document` | Existing `documents.get(includeTabsContent=true)` and renderer, unchanged | Existing root/child tabs and existing completeness rules; additional transport refusal is reported, not a silent cut |
| Google Sheets — `application/vnd.google-apps.spreadsheet` | `spreadsheets.get` lists ALL tabs in `properties.index` order, including hidden tabs; `values.batchGet` reads bounded A1 ranges for each GRID tab using `FORMATTED_VALUE`, row major. Render one Markdown section/table per tab with synthetic column-letter header so row 1 is data. Escape pipes/newlines deterministically | Sheet IDs; failed/missing range, non-GRID tab, changed revision, exceeded rows/cells/tab or byte limit => false. Empty GRID tab has heading and “(empty)”, not a missing-range error |
| Google Slides — `application/vnd.google-apps.presentation` | `presentations.get`, slides array order; walk page elements in returned order recursively through groups; render shape text and tables, then the speaker-notes BODY shape found using `notesProperties.speakerNotesObjectId`; section per slide | Slide IDs; missing expected notes shape/content, omitted text-bearing elements, cap or malformed page => false. A present empty notes BODY is valid; images/charts lacking readable equivalents get `unsupported_element` |
| PDF — `application/pdf` | Bounded `files.get alt=media`; pure-Python `pypdf`, page-order text-layer extraction, section per page | Page IDs; encrypted file => `encrypted_pdf` without password attempts; image-only page/document => `no_text_layer`; malformed/resource limit => false. A textless page with image content is incomplete even if other pages have text; a structurally blank page is valid |
| DOCX — `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | Bounded media download and safe OOXML XML parsing as described below; paragraphs and tables in document order; include headers, footers, footnotes and endnotes once in named sections | `document` segment plus ordered named auxiliary sections; corrupt/missing required parts, unsafe XML, archive cap, or unsupported text containers/embedded objects => false |
| XLSX — `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | Bounded media download and safe OOXML parsing; workbook relationship order, ALL worksheets including hidden ones; shared/inline strings, booleans, numeric values, formula cached values; one Markdown table per sheet with synthetic column letters | Sheet names; never evaluate formula or fetch external link. Missing cached formula value => `missing_formula_cache`; unsupported sheet type, missing part, cap or unsafe XML => false. Preserve raw numeric/date serial with cell style identifier when no safe display conversion is available and disclose display limitation |
| PPTX — `application/vnd.openxmlformats-officedocument.presentationml.presentation` | Bounded media download and safe OOXML parsing; presentation relationship slide order, shape/group/table text, followed by notes BODY text; one section per slide | Slide IDs; missing relationship/part, omitted readable object, cap or unsafe XML => false; exclude slide-number/date boilerplate from notes |
| Plain text — `text/plain`; Markdown — `text/markdown`, `text/x-markdown` | Bounded media download, deterministic decoding; retain source text (no execution) | `file`; undecodable data, text cap or download cap => false. Zero-byte plain text/Markdown is valid empty text |
| CSV — `text/csv`, `application/csv` | Bounded media download, deterministic decoding, Python CSV parser with comma delimiter and standard quote rules; Markdown table with numbered columns, all rows treated as data | `file`; malformed quoting or row/cell/text cap => false; non-UTF8 lossless fallback is disclosed; empty CSV is valid |
| HTML — `text/html` | Bounded media download and `html.parser`-based text extraction; headings, paragraphs and tables separated; drop script/style/template content; no network, script execution or external resources | `file`; decoding/cap failure or unbalanced essential content causing dropped text => false; empty HTML is valid empty text. Markup is never rendered as active HTML |
| JSON — `application/json`, `text/json` | Bounded media download and decoding; validate JSON, then retain original textual representation to avoid reordering or number-precision loss | `file`; malformed JSON => `invalid_json`; depth >100, parsing/text caps or zero-byte input => false |
| Images, audio/video, archives, Drawings, Forms, shortcuts, legacy Office (`.doc/.xls/.ppt` MIME types), macro-enabled Office, unknown/other MIME | Metadata-only; no media download or embedded extraction | `tabs=[]`, `complete=false`, `unsupported_mime`. Shortcuts are NOT resolved: own Drive ID/metadata only; no target fetch or target-membership inference |

Sheets ranges are quoted/escaped from provider tab names; do not treat names as raw A1 expressions. Batch requests are bounded and compared against the requested ranges: a missing returned range fails closed. GRID row/column bounds may overstate populated cells; if the implementation cannot prove the unvisited tail empty it reports a limit, rather than declaring complete. Read metadata/version before and after multi-call extraction; a changed version invalidates the extraction and schedules a retry through existing work, avoiding a mixed-version complete body. Slides completeness includes text and notes, not animation/layout fidelity. Unsupported embedded visual content is always disclosed; it is never captioned.

Google documents CSV/TSV export as first-sheet-only, and `files.export` limits exported content to 10 MB. This design uses native Sheets/Slides APIs rather than export, and local parsing rather than Office conversion. Any future export fallback must use a 10,000,000-byte ceiling and mark provider export refusal incomplete; it must not substitute a smaller export silently. [Drive export formats](https://developers.google.com/workspace/drive/api/guides/ref-export-formats), [Drive downloads](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

The Sheets API exposes metadata separately from values; notes have an explicit Slides BODY-shape identity. These are the API seams to test. [Sheets get](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get), [Sheets values](https://developers.google.com/workspace/sheets/api/guides/values), [Slides notes](https://developers.google.com/workspace/slides/api/guides/notes).

## Bounded resources and encoded-byte contract

At inspected staging `c5e832c2`, `app/api/v1/items/route.ts:24` defines `MAX_PAYLOAD=1_000_000`; line 49 defines `MAX_REQUEST_BYTES = ceil((MAX_PAYLOAD + MAX_PAYLOAD_ROWS * 700) * 1.2)`, currently **5,400,000 bytes**. Lines 61–65 compare Content-Length to that transport cap; the payload schema separately caps body string length at 1,000,000. The brief's implication that the request gate is 1 MB is stale: the error message's “body max 1 MB” names a different bound. Neither a Python character count nor JSONB's textual representation measures the actual request.

Derive the sidecar transport constant from the canonical server/API contract, with a cross-language drift test against the server expression/row constant; no unreviewed numeric copy. Before implementation changes the wire fields, update the pinned workspace `docs/brain-api.md` contract and version as RESOLVER requires. No API change is made by this docs-only PR.

For each new-format file let `R=MAX_REQUEST_BYTES`, `B=MAX_PAYLOAD`, and `E` be the encoded byte length of the exact outbound serialized payload with an empty body, including finalized frontmatter, issue report, authority envelope and JSON quotes. The text budget is `max(0, min(B, R-E))` **UTF-8 bytes**. Apply that budget on Unicode code-point boundaries. Then serialize the complete candidate with the exact BrainClient serializer and require `len(serialized_utf8) <= R` AND body UTF-16 length <= `B`. Escaping can expand text beyond `R-E`, so shrink the candidate and remeasure the entire serialized envelope, including the added `text_byte_limit` issue, until it fits. This safety check applies to all outbound Docs payloads too, without changing the Docs renderer's result. A new-format cap result is incomplete and follows the metadata/retained-body policy, not partial-text publication. If even the bounded metadata envelope does not fit, report `envelope_limit`, no item write, and failed outcome. Never cut required identity/authority or silently discard segments/issues to fit. Aggregate repetitive issues into a bounded count plus representative locations, with an explicit omitted-detail count.

All sizes below are exact byte limits; MiB means 1,048,576 bytes. Limits are checked on declared size when present AND actual streamed bytes (including decoded HTTP response bytes). Unknown/misleading Content-Length does not bypass a bound. Abort at cap+1; do not buffer first and check later.

| Resource | Default hard limit and response |
|---|---|
| Plain/Markdown/CSV/HTML/JSON download | 5 MiB per file, `download_byte_limit` |
| PDF or any supported OOXML download | 20 MiB compressed/input bytes per file, `download_byte_limit` |
| Native API response | 10 MiB decoded response per call, 40 MiB aggregate per file; `api_response_limit`; bounded batches of at most 20 Sheets ranges |
| Segments | 200 tabs/slides/pages per file, `segment_limit`; manifest explicitly identifies unprocessed count when available |
| Sheets/XLSX/CSV data | 2,000 rows per tab/table, 100 columns, 50,000 cells per file including allocated fetched cells, and 16,384 UTF-8 bytes per cell; `row_limit`/`cell_limit`; do not drop later tabs without an issue |
| OOXML archive | 2,000 entries, 100 MiB total actual inflated bytes, 10 MiB each entry, max compression ratio 100:1; `archive_limit` |
| Parser worker | One file per isolated subprocess, no network/credentials, 256 MiB memory ceiling, 30 seconds wall time; terminate and reap on resource limit; `parser_resource_limit` |
| Diagnostic envelope | At most 100 issue entries, 256 UTF-8 bytes per detail; aggregate count and omitted-detail count preserve the fact of incompleteness |

Choose `pypdf` for pure-Python packaging and text-layer extraction with no external OCR/runtime. Its content streams can inflate beyond input size, so download caps alone are insufficient; enforce worker memory/time limits before parsing. [pypdf text extraction](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md).

Choose a small read-only OOXML reader using Python `zipfile` plus `defusedxml.ElementTree` rather than library defaults whose XML paths need individual hardening. It is an equivalent local parser for this explicitly limited readable-text profile, not an Office renderer. Never extract archive paths onto the filesystem. Reject absolute/parent paths, duplicate ZIP names, symlinks, encrypted entries, inconsistent size/CRC, nested archives and unsupported compression. Count actual decompression bytes before XML parsing; validate central-directory bounds as an early check, not sole protection. Parse ALL consumed XML through defusedxml with DTD/entities/external references forbidden. Resolve only normalized in-package relationships; external relationships may be displayed as inert links but never fetched. No macros, formula evaluation or embedded code. Install `pypdf` and `defusedxml` in `ingestion/pyproject.toml`'s `gdrive` optional extra, with reproducible supported versions chosen at implementation. Verify production worker ceilings on supported deployment platforms; inability to enforce them fails closed for binary parsing, never silently runs an unbounded parser.

Encoding order: BOM-declared UTF-8/UTF-16 first, strict UTF-8 otherwise, then strict Windows-1252 as the documented fallback. Record the selected encoding and `encoding_fallback`. Never use `errors=ignore` or replacement characters. Undefined Windows-1252 bytes or binary NULs outside valid BOM-decoded UTF-16 produce `encoding_error`; no complete text. The fallback is an explicit limited policy, not reliable detection of every world encoding.

Edits update the canonical item; renames update title/link metadata without changing its ID; a move out of all selected scopes retracts the relevant claim; trash/removal follows the existing shared purge and cache/graph cleanup. Another active authorized claim can retain the item, but cannot preserve a revoked audience. Permissions are revalidated for every representation, even when extraction fails. Owner/creator/editor/last-modifier are source roles, never interchangeable. Preserve provider roles and unresolved references; `createdTime` does not imply creator identity. ## Admin and run reporting

Extend the existing report payload accepted by `POST /api/v1/integrations/gdrive/runs`, `gdrive_run_requests.summary`, and the existing Admin run ledger `ingest_runs.meta`. Add `formatCounts` keyed by `docs|sheets|slides|pdf|docx|xlsx|pptx|text|markdown|csv|html|json|other`, each with nonnegative `{ingested,incomplete,metadata_only,failed}`. Admin's existing run status reads the same saved summary; no new reporting authority or endpoint is required. The existing runs GET claims a pending connector request; it is NOT an Admin history endpoint and must not be widened to expose history.

Counts are disjoint terminal outcomes per distinct `(run, file ID)` attempted in that run, deduplicated across folders/pages/retries. `ingested` means complete text outcome accepted (created, updated OR unchanged); an incomplete metadata placeholder counts ONLY as `incomplete`, an unsupported MIME ONLY as `metadata_only`; transport/authority failures count ONLY as `failed`. Removed files remain in existing `removed`, not these extraction counts. A no-work incremental run has zero attempted-file counts; this is a run summary, not a whole-corpus inventory. A successful retry in the same run replaces that file's earlier failed outcome; a retry in a later run belongs to that later run. Persist/recover the aggregation with the existing durable run/work protocol so crashes and report replays cannot double count. Sum format counts equals distinct attempted files, not `created+updated`.

Any incomplete or metadata-only file makes extraction coverage `partial`; Admin distinguishes “enumeration complete; unsupported/incomplete files remain” from a provider failure. `authoritativeComplete` retains its existing enumeration/reconciliation meaning and may be true while extraction coverage is partial. No report labels those files' extraction complete. This distinction must survive the existing scheduled/manual status paths and idempotent report replay. Failed retained-body attempts show the provider modified time and issue without leaking file details outside Admin authority.

Per-type include/exclude UI is deferred to a follow-up selection-filter task: adding it changes generation hashing, membership removal and existing claims, so it is not a cheap checkbox. This version imports every selected non-folder MIME with an explicit outcome. Folder/file selection exclusions already apply to every type; excluded scope produces no new item and no extraction count. A previously imported file excluded by a changed selection is removed only through authoritative generation reconciliation, with other surviving claims respected.
