## What / why and outcomes

An eligible authored Slack message from a selected, verified-public channel must eventually produce evidence for the correctly linked person on its original contribution day. The evidence grain is `(thread, member, UTC day)`. Later replies cannot move previous days. Identity is attribution only: it never grants content access. Slack remains the existing in-app connector and `ingestItem` remains the item writer. No Python source, private-channel/DM ingestion, Events API prerequisite, new ACL model, or replacement of contributor correction locks is introduced.

This design chooses durable bounded polling and fair historical reconciliation. A full retained-history scan discovers old roots; a rotating revisit of ALL known roots discovers new replies even if history never resurfaces them. A larger first-page cap is not a fix. This proves eventual discovery, not arbitrary-corpus discovery in two ordinary scheduler ticks. The original two-interval latency is a proposed live target to measure, and must be reported as unmet if the measured cycle exceeds it. If a strict two-tick old-thread SLA becomes mandatory, the scope must add verified Slack Events delivery plus reconciliation; do not claim the polling design meets it by redefining an interval.

## Message ledger and canonical identity

Add a single source-owned metadata ledger, `slack_messages`, and durable polling state. Store durable cache generations in a new small `slack_team_state` table: `team_id` primary key/FK, `data_generation bigint not null default 0`, `identity_generation bigint not null default 0`. One source-owned generation helper increments these through the caller transaction; the message publisher and canonical identity/correction writers use it. Creation/read is team-scoped and indexed by the primary key; absent pre-activation row means generation0, DB read failure is an error. Cache payloads and memory entries store both stamps. Proposed schema (names may change in reviewed implementation, invariants may not):

* `slack_messages`: `team_id`, `workspace_id`, `channel_id`, `message_ts` (exact Slack string), `root_ts`, `item_id`, `author_external_id`, `occurred_at timestamptz`, `is_root`, `eligible`, `exclusion_reason`, `deleted_at`, `last_seen_generation`, `source_hash`, `observed_at`. ## Authorship, dates and corrections

Eligible personal work is a source-timestamped human-authored normal text message or thread broadcast (dedup the original ID). Preserve current bot text in the canonical transcript where already supported, but bot/system/service-account messages do not earn a person's work credit. Reactions and mentions do not earn credit. File-only messages and structural subtypes remain excluded with a reason; expanding attachment semantics is separate. Retain known guest/deactivated users as source identities and permit explicit/exact links to human roster members; do not auto-link bots. Tombstoned roots earn no current root evidence while live replies remain eligible. Extend `usersDetailed` to retain `is_bot`, `is_app_user`, `deleted` and restricted/guest flags. A `bot_message` subtype is excluded from personal credit even if it contains a user ID; unavailable bot classification stays unresolved rather than assuming human.

Normalize source instants to UTC and retain the exact message timestamp. Timeline grouping remains UTC (current grouper behavior), and displayed Slack times/day labels must agree; member-profile/browser timezone does not change stored work dates. Window semantics remain the existing rolling 7/30-day duration with fixed request `now` and explicit upper bound; capture `now` once for SQL and grouping. UTC midnight and DST/browser timezone tests pin this. Edits change content eligibility/hash but never `occurred_at`; deleting a message removes its current count/day if no eligible message remains.
