## What / Why

**What:** Retire the residual tier/posture read filter for positively admitted member content readers while preserving membership, provenance, token attenuation and export restrictions.

**Why:** A granted external collaborator currently receives inconsistent content across surfaces because residual posture filters override an otherwise valid membership grant.

**Build with:** Opus 5.5 / high, subscription-authenticated; Sol 6.1 fallback only as authorized by the workflow.

## Dependencies

**Deps:** AUDITFIX-3 grant/adoption prevention and AUDITFIX-13/item 12 item-context serialization are present at the inspected staging base; proof and retained invariants are below. Existing PostgreSQL adapter, membership oracle, and graph partition reader are reused. No new package or schema dependency.

## Outcome and re-derived facts

An eligible member in a group granted a project receives that project's member-readable content regardless of the person's tier label, everyone-group posture, or the item's team/external label. Removing the last applicable grant removes that project-scoped content; the separately preserved Everyone audience for hand-entered rows is stated below. Source provenance and token attenuation continue to apply. Labels continue routing automatic placement and public/export policy; they do not override a member's content grant.

The August ticket's line numbers and two-gate description are historical. PRET-4 already replaced members.tier with everyone-group posture at authentication boundaries. `visibleItemIdsForProjects` and item retrieval are already membership-only. Remaining posture walls in structured rows, grounding, by-id/dashboard reads and project counts make those surfaces disagree with membership-visible item retrieval. Do not implement by turning every tier helper into a passthrough.

Prerequisites are present in this base, despite historical specs saying otherwise:

* AUDITFIX-3: `lib/access/groups.ts` refuses unsanctioned system grants and `lib/access/bootstrap.ts` checks adoption before promoting a reserved source project. AUDITFIX-23 also detects existing forbidden edges; sanctioned repair exists. Their current tests must continue passing.
* AUDITFIX-13/item 12: dedicated-session transactions, ingest's path advisory lock and item row lock, and standalone context writer row locks coordinate item access, unit mirror and system membership moves. These replace the concurrency role attributed to `noWideningGate`. Preserve the protocol, protected target exclusions, rollback and directional close semantics.
* AUDITFIX-7: delegated tokens may receive hand-entered rows only within their effective project set. Everyone members retain their deliberate broader hand-entered provenance contract. Other admitted members gain only rows in their granted projects, as specified below.
* The current tree has no unauthenticated OKF page. `lib/okf/page.ts` serves the authenticated `/api/v1/okf-bundle` route. Preserve explicit `tier=external` export narrowing and link redaction. No new public access is introduced.

These are source-inspection findings, not claims that acceptance tests have already run or that historical production counts remain current.

## Authority and admission contracts

The existing oracle remains the sole owner of group/project/item visibility: team match, active eligible principal, grants, active item-grain unit and current include membership. Excluded, expired, retracted, unplaced and foreign-team content stays denied. `project_id` on an item/task is a container, not a replacement for source-item context membership. Preserve independent role, ownership, admin, audit and write privileges.

Introduce or reuse ONE explicit, fail-closed member-content admission resolver at trusted session/API boundaries. Its positive member-backed result requires a current same-team active `members` row satisfying existing `isPrincipal`: human or standing agent, not connector or offroster. Distinguish this content principal from delegated tokens and from legacy API credential validity. A valid `aios_` key alone is not positive member admission: current API auth does not select kind/is_connector, so inferring memberhood from a key/memberId would open unsourced content to connectors. Carry the checked result to shared readers with a discriminated context, not a boolean default that grants access when omitted. Missing, unknown or failed resolution must never enter the widened member arm. Database resolution errors fail the request/read closed through existing error handling; do not silently manufacture memberhood.

For legacy active connector/offroster API keys, preserve existing authentication and read restrictions, including their existing unsourced posture behavior; never grant new content because a tier filter was removed. Do not globally invalidate ingest credentials or change writes. An explicit legacy arm may retain the old filter and provenance semantics; it must not receive the new member arm or new graph authority. For supplied malformed/unknown admission values, fail closed. Standing agents are eligible explicit principals through custom grants; builtin auto-admission remains human-only.

For delegated `aiosd_` principals, retain launcher/on-behalf-of/scope intersection, current eligibility and revocation checks, admitted token posture policy, project-bounded unsourced rows, and omitted graph/organization mirror legs. Do not lift external delegation refusal as part of this work. Do not relabel tokens as members.

Sourced tasks/decisions are visible exactly when their source item is visible; remove the extra audience condition for admitted member readers. Null-source rows still require `created_by` proof. For positively admitted members whose actual builtin Everyone membership is accepted under the oracle's `isBuiltinEligible` human eligibility rule, retain `{kind: all}`; Everyone is their existing audience group. Other admitted members receive `{kind: projects, projectIds: grantedProjectIds}` from the same oracle resolution. Missing/empty grants close that arm. Tokens retain effective-project admission. No-provenance and deleted-creator rows stay hidden. Update TS and both SQL provenance forms, project/count queries and the timeline together. This is a membership rule, not a label veto; flipping members.tier alone changes no read. AC-04 is explicitly revised from the original all-members proposal: that proposal would disclose every unsourced project to grantless external humans/agents and is rejected. Preserve existing write authorization: `canSeeProjectRow` is also used by task/decision create actions. Keep `canSeeProjectRow` writer behavior on its legacy predicate and introduce a separate widened read/count helper where needed so newly readable containers do not silently become new write destinations; test a source-container content-visible case, not just a directly granted project.
