## Findings and decisions

### 1. High — deferred folder membership can produce inferred removal: fix now

**Confirmed.** gdrive_sync.py:2694–2708 materializes retained membership without traversal additions; state.py:2029–2058 retains only provider/root/drive triples. roots_for_parent at state.py:2156–2165 reads the active snapshot's traversal_queue. Thus a nested retained document can be selected but have no recognized parent in gdrive_sync.py:2326–2350. absence_withheld at 2182–2244 can read the root present, call settle_root, and return false. settle_root correctly refuses to settle deferred evidence (state.py:1103–1119), but that refusal does not change the caller's held flag. The remove obligation and membership removal then occur at 2360–2363. The complete-snapshot gate does not protect this per-document removal path.

The timeout case is real because _restrict_resource accepts only provider_deadline evidence (309–321), leaving no resource restriction for a timeout. Expiry between the stream's admissibility check and change processing exposes the same path. Existing F4 tests exercise restricted file roots, for which direct selection bypasses this ancestry gap.

**Bounded correction:** use the existing retained membership root_ids plus the durable deferred-root obligation as an explicit conservative admission input. For a previously selected document whose out-of-scope classification depends on a deferred root's incomplete enumeration, withhold inferred removal and retain its membership/claim and the owed root recovery even when the root's metadata now reads present. Holding the document until verified enumeration is acceptable; do not require speculative upsert to close this finding. A metadata read is not subtree enumeration. Avoid repeatedly forcing a new whole-stream rescan from each held change while that root remains deferred; the existing root recovery obligation owns continuation.

If the writer elects to carry traversal/ancestry instead, it must retain the exact published snapshot's per-root provenance, mark it as retained rather than current, and never treat stale ancestry as authority to import previously unknown documents. Copying traversal rows as newly completed/current evidence is not an acceptable shortcut. The conservative hold path is preferred because it does not need a new authority representation. Preserve any existing ancestry and overlapping claims; do not invent ancestry on fresh SQLite state.

Do not broaden this into suppressing all positive removal evidence forever. Keep the existing verified root-loss, explicit removal, relocation and cross-connection claim rules, including the current restriction gate. After admissible verified enumeration resolves the root, genuine disappearance must reconcile and restoration must work. No root-complete flag, claim retirement or authoritative success may be inferred from the deferred page's completion.

### 3. Medium — drain-phase account hold lacks publication recovery: fix now, narrow the proposed test

**Bounded correction:** compare acknowledged versus local standing holds as well as resources, with separate truthful categories for each unpublished kind. Recover publication both after a drain failure and on the standing-hold early-return path after fresh acquisition. Attempt no provider call while the hold stands. Restriction-only publication must start from the latest acknowledged progress and preserve sibling streams, roots and watches; merge minima monotonically, including retained accounts. Count an outstanding hold once per run, rather than once per attempted publication. Preserve the checkpoint error category as well as the unpublished diagnostic.

Do not simply change the comparator to true and label an account hold document_restriction_unpublished. Do not retry changed checkpoints in a loop. BrainClient.checkpoint_gdrive_execution at 551–562 forbids further publication under an uncertain revision; reacquisition is required. Tests must use the actual latch for lost-acknowledgment cases.

**Durability qualification:** Fable's proposed immediate fresh-state assertion after a checkpoint that never committed is impossible if the only local journal has also been discarded. This was already an explicit R49 limitation. Require fresh-state no-early-call proof after (a) a checkpoint committed but its response was lost, or (b) a surviving local journal reacquired authority and successfully republished. When neither side retained the observation, do not claim recovery. A failed publication must remain visibly unpublished; it cannot be called acknowledged recovery.

### 4. Medium — timeout deferral repeatedly rebuilds siblings: narrow fix now

**Confirmed.** _deferred_root_admissible at 564–577 is true for any deferred root without a standing provider minimum. The rescan at 1933–1950 seeds all current roots. A persistent timeout can repeatedly relist healthy siblings across polls. This is bounded per run, not an established tight infinite loop, but it is a distinct enumeration amplification issue. R49 F6 deferred repeated accepted-content checkpoint refusal, not every repeated operation.

**Exact scope:** before a deferred root alone triggers a whole-stream recovery snapshot, perform a bounded root-local admissibility probe through the existing provider gate, deadline and retry limits. An unsuccessful nonquota probe retains the deferred obligation, records any newly supplied provider minimum, and permits independent changes draining without relisting healthy siblings solely for that deferral. A successful probe may authorize starting the normal controlled rescan; it does not settle the root or establish current membership. A verified root loss or relocation must use the existing evidence path. Quota still stops the account. A standing resource restriction forbids the probe until eligible. Limit the probe to once per relevant root per run at coordinator level; provider-internal retries remain bounded by their existing contract.

The writer may instead implement an equivalent persisted local root backoff within the existing root/stream owner, but must document its provenance separately from provider minima and prove healthy siblings continue progressing. No generic outage detector, retry service, override control or new retry-budget owner is authorized. Root recovery must remain eligible after repair; no exhaustion policy may drop the unresolved root. Test the chosen bounded policy rather than silently retaining today's unconditional full rescan.

F6 remains deferred behind its existing **before unattended rollout** gate: bounded repeated deterministic checkpoint refusal, actionable reporting, preserved acknowledgment obligation, idempotent replay, and eventual recovery without charging document failures or false completion. This adjudication does not clear that gate.
