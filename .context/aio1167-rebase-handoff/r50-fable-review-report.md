**1. High (F4): a deferred FOLDER root loses its subfolder ancestry, so a later edit to a nested retained document is classified as out of scope and becomes a REMOVE.**
- Evidence: the deferred traversal is closed with an empty page carrying only `retained_root_membership` for the top row and no `traversal_additions` (`ingestion/aios_ingest/gdrive_sync.py:2694-2708`). Scope on a change page is derived from `roots_for_parent`, which reads `traversal_queue` rows of the active snapshot (`ingestion/aios_ingest/state.py:2156-2165`). A retained nested document then has `selected=True, in_scope=False` (`gdrive_sync.py:2326-2350`). `absence_withheld` holds only for a leaving, restricted or unreadable root; a root that reads present hits the `else: settle_root(...)` branch, which refuses the deferred root but leaves `held` False (`gdrive_sync.py:2192-2244`), so the removal obligation is appended (`gdrive_sync.py:2360-2364`).
- Trigger: recursive folder root with `sub/doc-n`; baseline completes; a 410 rescan reads the folder root's metadata into a `provider_timeout` ProviderDeferred (no provider minimum, so `_restrict_resource` records nothing and the root is deferred but not restricted); the rescan publishes; in the same run a change page reports an edit of `doc-n`; the root's metadata now reads fine. Also reachable for a restricted root whose minimum lapses between the admissibility check at `gdrive_sync.py:1940` and the change page.
- Expected: the adjudication requires "do not fabricate baseline completeness or absence"; the claim stands until the root is enumerated again.
- Actual: `doc-n` is removed from the snapshot and a remove is pushed, then the next run's rescan rediscovers and re-upserts it. Content flaps through a purge from a non-verified listing, which AC-05 forbids.
- Regression: in `test_restricted_root_recovery.py`, a recursive folder root with a nested document, defer the root by a timeout during a 410 rescan, then edit the nested document; assert no `remove` obligation, the document is not in `world.removed`, and the obligation is either an upsert or held. Add the same case for a restricted root whose minimum lapses mid-run.
- Note: file roots are unaffected because `direct` keeps them in scope. The existing F4 tests use only file roots (`file-x`), which is why this went green.

**2. Medium (F3): a root deferral's Retry-After minimum is lost when a later root answers with a quota error or an authority error during binding.**
- Evidence: `_bind_selected_roots` and `_reobserve_stalled_relocations` only append to `deferred_roots` (`gdrive_sync.py:884-890`); `_restrict_resource` for those roots runs in the loop at `gdrive_sync.py:1346-1352`, after the `try`. A `rate_limited` or `BrainError` from a later root returns at `gdrive_sync.py:1338-1345` before that loop runs.
- Trigger: file root A answers 503 with `Retry-After: 99999999`; file root B answers 429 with `Retry-After: 60`.
- Expected: A's minimum is recorded as A's restriction regardless of what B said.
- Actual: only `mark_root_unresolved` with a text detail was written for A; after the 60-second account hold lapses, A is read again. This is exactly the early retry F3 was accepted to prevent.
- Regression: two file roots as above through `_DriveWorld`; after the run assert `"file-x" in document_restrictions(...)`; advance the clock past the hold; assert no `("metadata","file-x")` call. Fix by recording the minimum inside the binding helpers at the point of deferral, or by running the loop in a `finally`.

**3. Medium (F7, F1): an account hold learned in the drain phase whose publication fails is never reported and never republished.**
- Evidence: the drain-phase hold is written locally and its checkpoint failure is swallowed unless terminal (`gdrive_sync.py:1512-1531`); `_restriction_unpublished` compares resources only, never holds (`gdrive_sync.py:949-963`); every following run returns at `gdrive_sync.py:1245-1250` before any checkpoint.
- Trigger: a 429 during a drain while the brain returns 503 on the checkpoint.
- Expected: the adjudication's F7 asks that unconfirmed remote durability be reported; the account-hold path already has the `account_hold_unpublished` category for the pre-stream case.
- Actual: the run reports `rate_limited` only. The hold stays local until it lapses, so a fresh state file restored from the brain makes an early call. `test_account_hold_before_streams.py::test_a_failed_publication_keeps_the_local_hold_and_says_so` covers only the pre-stream path.
- Regression: drain-phase 429 via `world(..., fail="list")` plus `checkpoint_error`; assert `account_hold_unpublished == 1`; then a fresh state file makes no provider call. Extend `_restriction_unpublished` to include holds so the end-of-run publication retries them.

**4. Medium (F4): a root deferred without a provider minimum re-triggers a whole-stream controlled rescan on every poll.**
- Evidence: `_deferred_root_admissible` is true whenever any deferred root is not restricted (`gdrive_sync.py:1086-1099`), and the stream then re-seeds every root of the stream (`gdrive_sync.py:1933-1950`). A timeout records no minimum, so this repeats each run until the root reads.
- Impact: bounded per run by the page budget, as the writer notes in boundary 3, but unbounded across runs and it relists every sibling root each poll. This is the same class of repeated retry without backoff that Astra deferred under F6, applied to enumeration rather than checkpoints.
- Recommendation: persist a per-root not-before on the deferred binding (reuse `_backoff_seconds`) or re-read only the deferred root before deciding to rescan. Astra should say whether this is accepted under F6's deferral or must be fixed here.

**5. Low (F2): Run now does not retry a non-exhausted document that is inside its backoff.** `rearm_exhausted` touches only rows with `exhausted_at` set (`state.py:1705-1722`). **7. Low (F3): `_stream_start_deferred` reports every local-deadline category as `run_deadline`** (`gdrive_sync.py:1117-1120`), so a `dispatch_deadline` stop is mislabelled. Diagnostic only.
